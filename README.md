# DLNAtube

Минималистичное приложение для macOS, которое воспроизводит видео с YouTube на телевизорах и других устройствах DLNA/UPnP MediaRenderer.

**English:** The application supports an English interface. See the [English README](README.en.md).

![DLNAtube screenshot](./Screenshots/03.png?raw=true)

## Сборка и запуск

Требуются macOS 13 или новее и Xcode Command Line Tools со Swift 5.9+, `clang` и `make`.

```sh
sh scripts/build-app.sh
open dist/DLNAtube.app
```

Папка `Vendor/` не хранится в Git. YouTubeKit 0.4.9 подключается как Swift-пакет. Перед сборкой `scripts/prepare-youtubekit.sh` получает закреплённую версию и применяет патч для прокси, длительности видео, перемотки и ресурсов приложения стандартной утилитой `patch`. Исходники пакета остаются в `.build/`, а файл патча `scripts/youtubekit.patch` хранится в репозитории. Скрипт `scripts/setup-vendor.sh` скачивает архив FFmpeg 8.1.3 в `Vendor/FFmpeg`; `scripts/build-app.sh` запускает его автоматически, если архива ещё нет. Если в проекте нет готовой FFmpeg-библиотеки для текущей архитектуры, она будет собрана из архива; первая такая сборка займёт больше времени.

Чтобы запустить тесты:

```sh
sh scripts/prepare-youtubekit.sh
swift test
```

## Использование

Mac и телевизор должны быть в одной локальной сети. При первом запуске разрешите приложению доступ к локальной сети; macOS или брандмауэр также могут спросить о входящих подключениях. Приложение автоматически ищет устройства при запуске. Если телевизор не появился, нажмите «Найти устройства».

Выберите устройство и вставьте HTTPS-ссылку на видео YouTube. Под списком отображаются форматы, которые устройство объявляет в профилях DLNA, и сведения о разрешении из этих профилей. Это не обязательно точное максимальное разрешение экрана телевизора.

Поле ссылки хранит до 100 уникальных недавно воспроизведённых URL. Запись добавляется после успешного начала воспроизведения. При фокусе на пустом поле показываются последние 10 названий; при вводе поиск проверяет название и URL по любой введённой группе символов, отделённой пробелами.

Кнопки в приложении управляют воспроизведением, паузой и остановкой. Состояние воспроизведения и позиция опрашиваются у телевизора и отражаются в приложении. Длительность берётся из метаданных YouTube, если телевизор её не сообщает. При выходе приложение отправляет телевизору команду остановки.

Ползунок перемотки работает по-разному в зависимости от потока. Для MP4 приложение отправляет телевизору команду DLNA Seek. Для раздельных видео- и аудиодорожек оно запускает новый MPEG-TS-поток с ближайшего ключевого кадра; фактическая позиция может отличаться от выбранной на несколько секунд. На проверенном Samsung UE46EH5307 перемотка такого MPEG-TS с пульта телевизора не работает.

Настройки открываются кнопкой-шестерёнкой или сочетанием `⌘,`. В них можно выбрать русский или английский язык интерфейса и указать прокси. До первого сохранения приложение использует русский для основного русского языка macOS и английский для остальных языков. По умолчанию используется прокси `http://localhost:10809`. Принимаются адреса с `http://`, `https://` и `socks5://`; пустое поле использует системные настройки сети. Прокси применяется к запросам Mac к YouTube, а телевизор получает поток от Mac через локальную сеть. Язык и прокси применяются вместе после нажатия «Сохранить», затем окно настроек закрывается.

## Передача видео и ограничения

Для получения ссылок на потоки используется встроенная библиотека [YouTubeKit](https://github.com/alexeichhorn/YouTubeKit) 0.4.9 и её локальный метод извлечения. Если YouTube предоставляет совместимый общий MP4-поток H.264/AAC, приложение передаёт его телевизору напрямую с поддержкой HTTP Range. Если видео и звук доступны отдельно, приложение считывает их по диапазонам и объединяет в MPEG-TS библиотекой FFmpeg во время передачи. Полный ролик не скачивается и не сохраняется на диск; декодирования и перекодирования нет.

Приложение выбирает самое высокое совместимое разрешение, которое не превышает заданное для выбранного устройства. Если меньших вариантов нет, используется наименьшее доступное более высокое разрешение. Выбранное ограничение качества сохраняется отдельно для каждого устройства. Поддерживаются варианты до 4320p (8K) и только совместимые потоки H.264 и AAC. Прямые эфиры и DRM-защищённое видео не поддерживаются. YouTube меняет внутренний API, поэтому извлечение ссылок может временно перестать работать до обновления библиотеки.

Safari и WebKit в текущем варианте не используются: приложение получает потоковые URL через YouTubeKit и передаёт данные телевизору через локальный HTTP-сервер.

## Встроенные библиотеки и лицензии

YouTubeKit 0.4.9 подключается из [upstream-репозитория](https://github.com/alexeichhorn/YouTubeKit) как точная версия Swift-пакета; приложение использует только локальное извлечение и не вызывает удалённый сервис библиотеки. `scripts/prepare-youtubekit.sh` применяет `scripts/youtubekit.patch` стандартной утилитой `patch`: изменение сохраняет настройки прокси, добавляет длительность в метаданные и поддерживает перемотку и загрузку ресурсов из собранного `.app`. Исходники пакета и результаты сборки остаются в игнорируемой папке `.build/`; `Vendor/` также исключена из Git.

Для объединения потоков используется локально собранная библиотека из [FFmpeg 8.1.3](https://ffmpeg.org/download.html). Сборка отключает GPL-компоненты, программы, декодирование и перекодирование. Скрипт подготовки скачивает исходный архив в `Vendor/FFmpeg`; сборка библиотеки выполняется через `scripts/build-media-library.sh`. Тексты лицензий хранятся в `Resources/ThirdPartyLicenses` и включаются в `.app`; архив FFmpeg и отдельная команда `ffmpeg` в приложение не входят.

## Разрешение локальной сети и подпись

По умолчанию приложение подписывается локальной ad hoc-подписью. macOS может повторно запросить разрешение «Локальная сеть» после обновления приложения. Для более стабильного разрешения используйте сертификат Apple Development:

```sh
DLNATUBE_CODESIGN_IDENTITY="Apple Development: …" sh scripts/build-app.sh
```
