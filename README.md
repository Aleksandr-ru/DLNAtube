# DLNAtube

Минималистичное приложение для macOS, которое воспроизводит видео с YouTube на телевизорах и других устройствах DLNA/UPnP MediaRenderer.

## Сборка и запуск

Требуются macOS 13 или новее и Xcode Command Line Tools со Swift 5.9+, `clang` и `make`.

```sh
sh scripts/build-app.sh
open dist/DlnaTube.app
```

Если в проекте нет готовой FFmpeg-библиотеки для текущей архитектуры, скрипт соберёт её из архива `Vendor/FFmpeg/ffmpeg-8.1.3.tar.xz`. Первая такая сборка займёт больше времени. Сборка приложения автоматически увеличивает третий компонент версии и записывает новые значения в `Resources/Info.plist`.

Чтобы запустить тесты:

```sh
swift test
```

## Использование

Mac и телевизор должны быть в одной локальной сети. При первом запуске разрешите приложению доступ к локальной сети; macOS или брандмауэр также могут спросить о входящих подключениях. Приложение автоматически ищет устройства при запуске. Если телевизор не появился, нажмите «Найти устройства».

Выберите устройство и вставьте HTTPS-ссылку на видео YouTube. Под списком отображаются форматы, которые устройство объявляет в профилях DLNA, и сведения о разрешении из этих профилей. Это не обязательно точное максимальное разрешение экрана телевизора.

Поле ссылки хранит до 100 уникальных недавно воспроизведённых URL. Запись добавляется после успешного начала воспроизведения. При фокусе на пустом поле показываются последние 10 названий; при вводе поиск проверяет название и URL по любой введённой группе символов, отделённой пробелами.

Кнопки в приложении управляют воспроизведением, паузой и остановкой. Состояние воспроизведения и позиция опрашиваются у телевизора и отражаются в приложении. Длительность берётся из метаданных YouTube, если телевизор её не сообщает. При выходе приложение отправляет телевизору команду остановки.

Ползунок перемотки работает по-разному в зависимости от потока. Для MP4 приложение отправляет телевизору команду DLNA Seek. Для раздельных видео- и аудиодорожек оно запускает новый MPEG-TS-поток с ближайшего ключевого кадра; фактическая позиция может отличаться от выбранной на несколько секунд. На проверенном Samsung UE46EH5307 перемотка такого MPEG-TS с пульта телевизора не работает.

Настройки прокси открываются кнопкой-шестерёнкой или сочетанием `⌘,`. По умолчанию используется `http://localhost:10809`. Принимаются адреса с `http://`, `https://` и `socks5://`; пустое поле использует системные настройки сети. Прокси применяется к запросам Mac к YouTube, а телевизор получает поток от Mac через локальную сеть. После успешного сохранения окно настроек закрывается.

## Передача видео и ограничения

Для получения ссылок на потоки используется встроенная библиотека [YouTubeKit](https://github.com/alexeichhorn/YouTubeKit) 0.4.9 и её локальный метод извлечения. Если YouTube предоставляет совместимый общий MP4-поток H.264/AAC, приложение передаёт его телевизору напрямую с поддержкой HTTP Range. Если видео и звук доступны отдельно, приложение считывает их по диапазонам и объединяет в MPEG-TS библиотекой FFmpeg во время передачи. Полный ролик не скачивается и не сохраняется на диск; декодирования и перекодирования нет.

Приложение предпочитает самое высокое совместимое разрешение до 720p. Если такого потока нет, выбирает поток с наименьшим доступным разрешением. Поддерживаются только совместимые потоки H.264 и AAC. Прямые эфиры и DRM-защищённое видео не поддерживаются. YouTube меняет внутренний API, поэтому извлечение ссылок может временно перестать работать до обновления библиотеки.

Safari и WebKit в текущем варианте не используются: приложение получает потоковые URL через YouTubeKit и передаёт данные телевизору через локальный HTTP-сервер.

## Встроенные библиотеки и лицензии

Исходники YouTubeKit включены в `Vendor/YouTubeKit-0.4.9` под лицензией MIT; приложение использует только локальное извлечение и не вызывает удалённый сервис библиотеки.

Для объединения потоков используется локально собранная библиотека из [FFmpeg 8.1.3](https://ffmpeg.org/download.html). Сборка отключает GPL-компоненты, программы, декодирование и перекодирование. В `Vendor/FFmpeg` находятся исходный архив и тексты лицензий LGPL 2.1; сценарий сборки — `scripts/build-media-library.sh`. В `.app` входят собранная библиотека и тексты лицензий, но не исходный архив FFmpeg и не отдельная команда `ffmpeg`.

## Разрешение локальной сети и подпись

По умолчанию приложение подписывается локальной ad hoc-подписью. macOS может повторно запросить разрешение «Локальная сеть» после обновления приложения. Для более стабильного разрешения используйте сертификат Apple Development:

```sh
DLNATUBE_CODESIGN_IDENTITY="Apple Development: …" sh scripts/build-app.sh
```
